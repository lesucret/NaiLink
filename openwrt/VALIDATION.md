# 0.6.33 维护失败恢复复查

日期：2026-10-26；分支：`codex/maintenance-recovery`。
测试发行：[openwrt-v0.6.33](https://github.com/slobys/NaiLink/releases/tag/openwrt-v0.6.33)。

- **已复现缺口**：旧实现在备份失败后保留数据，但没有恢复已经停止的服务；安装失败也只保留归档。新增停服前失败的原服务状态恢复，以及在线更新的已校验旧原生包缓存和回退。回退恢复配置/SQLite/WAL，保留失败现场归档；回退也失败则停止服务并明确报错，不称为恢复成功。下载、旧包缺失或校验失败发生在停服前。自定义外部配置/数据库符号链接拒绝自动覆盖，保留原服务与外部数据。
- **终止恢复**：维护 worker 接管 TERM/INT/HUP，安装子进程单独进程组，先 TERM 让安装脚本执行恢复 trap，再有界清理残留子进程；procd 留出恢复时间。队列时间遇到时钟回拨也不会永久占用。
- **规则库确认**：私有 `activation.json` 在切换前记录 applying，控制面重新就绪后记录 applied；回退记录 rolled_back。启动时恢复未完成批次，响应丢失按确认记录恢复任务结果。未确认时阻止重复维护，不把候选文件冒充已生效版本。激活仍复用当前运行配置，保留尚未应用的修改；加载前再次检查用户自定义文件。
- **浏览器恢复**：原生 LuCI 页面在 daemon 暂停或启动中继续显示更新进度，完成后重载；错误结果在再次打开窗口时保留。适配 LuCI 的 `reject` 选项、SessionError 和 RPC 权限代码，登录过期停止无效轮询，提供状态重读/重新加载入口，尊重原生登录弹窗。日志 JSON 载荷续行保留原级别和文本；RPC 非零状态或缺失载荷不会清空已有日志，下一次有效读取继续刷新。
- **系统与故障回归**：隔离原生 BusyBox/UCI 测试覆盖备份失败、部分安装失败、HTTP 未就绪、坏回退包、二次回退失败、停用状态和外部数据库保护。真实 APK v3 与 rootfs opkg 分别验证低版本原生包可恢复版本及载荷。Go 并发回归覆盖命令取消 trap、子进程退出、确认丢失、恢复结果和进程启动前的规则回退。
- **浏览器边界**：真实 LuCI/rpcd/procd 与私有 HTTPS 未来发布夹具验证电脑和手机触控尺寸的失败重试、刷新和会话恢复；未来安装器为替身，原生安装失败/回退另外由隔离包管理测试覆盖。API-only daemon 在未确认规则指针处强制退出再启动，检查旧批次恢复及用户表摘要一致，不代表实际 eBPF/LAN 流量测试。
- **发布门禁**：保留五架构、十个 SDK、协议互通、内核能力探针和安装包逐文件校验。README/在线说明更新；多内核仅保存[技术规划](../docs/multi-core-plan.md)，没有加入未验证内核或按钮。

保留现有节点、订阅、群组、DNS、路由与数据库结构，无新依赖。未更新用户路由器。磁盘损坏、硬断电或包管理器自身无法回退时，仍须使用保留的备份人工修复；不保证所有中断均可自动恢复。ARMv7/MIPS 透明代理限制保持不变。

# 0.6.28 DNS 查询隔离与连接诊断

日期：2026-10-21；分支：`codex/dns-query-isolation`。

- **启动与恢复**：外部就绪检测最多等待 10 秒，失败后继续加载已有配置；核心健康检查继续尝试连接。默认监听逻辑 `wan` / `wan6` 上线，恢复后重新识别自动 WAN 设备；自定义逻辑接口使用 `wan_network` / `wan6_network`。普通 WAN `interface.update` 不触发重启，网络重载与安装锁互斥。

## GeoSite / GeoIP 路径衔接

用户点击启动代理时，后端报告在 `/etc/daed`、XDG 和 `/usr/share/daed` 找不到

## 订阅下载修复

用户路由器只读诊断：同一条订阅，系统路径的 Daed / PassWall 请求头均得到
403 / AUTH_FAIL，经已运行 PassWall 的本机 SOCKS 则得到 HTTP 200、Base64、
72 条节点链接；另一条订阅在三种路径下均成功。这定位到可用下载出口差异，
并不表明改 User-Agent 就能修复。

新增自动回退，沿用原有系统路径和 dae 路由，失败后读取 PassWall 当前的回环
SOCKS 地址重试。DNS 由 SOCKS 出口处理，HTTPS 保留证书验证。可选 `passwall`
模式只用该出口，`off` 保留原路径。没有 PassWall 时不影响原本成功的下载。
不修改数据库结构、订阅链接或其他代理服务配置，无新增 npm / Go 依赖。

## 自动化与原生验证

- 6 项后端测试（另含地址校验子用例）：真实本地 SOCKS5 协议与远程域名解析、
  自动回退/原路径优先、强制代理失败不切换出口、动态读取端口、重定向 cookie、
  请求头、环境代理不干扰、错误凭据遮盖、TLS 校验和 4 MiB 响应上限。
  通过真实 SQLite 执行新增、手动更新和已注册的定时更新任务，失败时核对旧节点。
- 56 项 Python 测试：隔离 OpenWrt rootfs 内运行真实 BusyBox/UCI/jsonfilter/
  ucode/rpcd/APK。新增 5 项下载出口发现测试；ShellCheck 与 8 项 LuCI 脚本测试。
- x86_64 / ARM64 静态程序；22 个原生 IPK/APK，检查每个包的架构、依赖、脚本、
  权限和新下载助手文件。R4S APK 使用 `aarch64_generic`，不强制忽略内核 ABI。

## 复现浏览器升级测试

需要 Linux root、预先校验并安装完整 LuCI 的隔离 rootfs、旧/新运行程序及
新网关。测试只写入专用 `--workspace`，目录必须不存在；可用 JSON 控制命令
停止服务。Windows 浏览器端使用项目现有 Playwright，未增加依赖。

```sh
python3 tests/openwrt/native_panel.py --rootfs /path/to/rootfs \
  --old-runtime /path/to/0.2.1/daed --runtime /path/to/0.3.0/daed \
  --proxy /path/to/0.3.0/luci-proxy --workspace /path/to/new-test-directory \
  --control /path/to/shared-control
DAED_PANEL_CONTROL=/path/to/shared-control node tests/openwrt/browser-panel.cjs
```

可用 `DAED_BROWSER_EXECUTABLE` 指定浏览器。HTTP 端口 18080，HTTPS 18443，
订阅源 18081，内部 API 12025。夹具为测试身份和本地订阅，不使用真实代理凭据。

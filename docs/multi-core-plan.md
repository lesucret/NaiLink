# NaiLink 多内核规划

日期：2026-10-26。状态：0.6.34 已完成统一管理层与首版 dae / sing-box 切换；mihomo 仍是后续规划。[本版范围与限制](core-switching.md)。

可以实现“一个面板，切换 dae / sing-box / mihomo”。建议采用可选内核、同一时刻只由一个内核接管网络。目标是扩大常见协议与配置的兼容范围，不能承诺支持所有协议、所有扩展或让失效节点恢复。

## 建议的开发顺序

1. **先抽出内核管理层**：保留 NaiLink 的 LuCI 登录、节点/订阅/群组与数据库，统一启动、停止、配置校验、就绪、日志、测试和流量接口。现有 daemon 把管理 API 与 dae 控制面放在一个程序中，运行状态和统计直接读取 dae；不能仅换一个可执行文件。管理程序与内核依赖也要拆分，安装器按所选内核检查，不能要求另两核安装 dae 的全部 eBPF/BTF 依赖。
2. **先接入 dae + sing-box**：dae 保持默认。sing-box 作为可选包单独下载、固定版本和 SHA-256，先完成 x86_64 / ARM64、常见节点、DNS、基础分流及失败回退；验证后再开放切换按钮。
3. **再接入 mihomo**：在同一管理层上增加适配，优先解决 Clash 配置/订阅、代理组和规则集合的兼容。每个内核保存自己的原生配置和高级选项，切回时恢复原样。

## 三种内核怎样选择

| 内核     | 主要用途                            | 集成时的区别                                                   |
| -------- | ----------------------------------- | -------------------------------------------------------------- |
| dae      | 保留现有 eBPF 透明代理与分流体验    | 内核/eBPF/BTF 前置条件仍须实际检查；现有配置和行为作为兼容基线 |
| sing-box | 扩展协议组合和统一代理配置          | JSON 配置、TUN/透明代理、DNS、选择器和规则集都要适配           |
| mihomo   | 兼容 Clash 生态的订阅、代理组与配置 | YAML 配置、providers、DNS、TUN/透明代理和控制 API 需分别处理   |

协议覆盖按**固定内核版本、构建标签和传输参数**维护能力表；某个协议名相同，不代表证书、传输、插件、复用或 UDP 行为完全相同。节点可以保留并展示“不兼容原因”，不能静默删除或改写参数。[sing-box 出站说明](https://sing-box.sagernet.org/configuration/outbound/)、[mihomo 出站说明](https://wiki.metacubex.one/config/proxies/)。

## 数据和规则如何保留

- 节点链接、订阅来源、群组成员继续以 NaiLink 数据库为主，不反复把三份原生配置互相转换。先保存原始参数，再生成目标内核运行配置。
- 通用功能共用界面；高级 DNS 和原生路由按内核保存。不能等价迁移的规则、自动选择策略与参数，应阻止切换或让用户明确解决，不能悄悄忽略。
- 规则库分开管理：本项目当前使用的 `.dat` 方案不能直接当成三核通用方案。sing-box 已移除旧 GeoIP/Geosite 配置，需适配 `rule_set` 和对应格式；mihomo 的规则集合也有自己的格式和行为。[sing-box 路由](https://sing-box.sagernet.org/configuration/route/)、[Geosite 迁移](https://sing-box.sagernet.org/configuration/route/geosite/)。
- 内核、规则库和管理面板分别显示版本、来源与更新状态。复用经过校验的下载和失败恢复机制，不同时更新多个活动内核。

## 切换流程与回退

建议界面为：**当前内核及版本 → 选择目标 → 检查兼容性 → 切换**，显示不兼容节点/规则、预计短暂断连和当前安装状态。未安装的内核先提供“安装并检查”，不能把一个无效选择显示成已生效。

1. 保存用户配置、当前内核/版本、DNS/路由接管信息和恢复记录；验证目标配置与可执行文件。
2. 先在隔离端口做目标内核的配置和基础连接检查，不接管 LAN。
3. 停止原内核，确认其监听、BPF/TUN 与本项目的路由/DNS 规则已退出；只清理 NaiLink 自己创建的资源。
4. 启动目标内核并验证实际监听、DNS 解析和路由接管，成功后才提交“当前内核”。
5. 失败则撤销目标资源，恢复旧配置、旧内核及原接管方式；下次启动也要能识别并恢复中断的切换。

三核都可能影响网络接管。sing-box 的 Linux TUN 可设置 nftables/fw4 兼容规则；mihomo 的 TUN 也涉及路由、DNS 劫持和 iptables/nftables。必须检查端口、路由表、标记和其他正在运行的代理，不能让它们同时抢占相同流量。[sing-box TUN](https://sing-box.sagernet.org/configuration/inbound/tun/)、[mihomo TUN](https://wiki.metacubex.one/config/inbound/tun/)。

切换会中断已有连接，也可能改变自动群组选择和公网出口。AI 分流应保留同一个兼容节点或明确提示策略差异；不能承诺切核后浏览器会话、出口信誉或网站风控提示保持不变。

## 验证与发布范围

先验证 x86_64 / ARM64 的 OpenWrt、ImmortalWrt、iStoreOS，并区分 IPK/APK 和 fw4 条件。ARMv7/MIPS 要重新检查所选内核的实际构建、TUN/防火墙能力与资源需求；不能沿用“dae 无法加载 eBPF”推断另两核一定可用或不可用。

验收应覆盖：原节点/订阅/配置逐项保留、真实独立服务端的 TCP/UDP、IPv4/IPv6、DNS 分流、AI 群组、规则库更新、冷启动、WAN 断线恢复、fw4 重载、切换失败、进程退出、管理会话过期和电脑/手机交互。内核许可证及对应源码/构建要求也应纳入分发检查。

**首版先满足已能安装 NaiLink 的 x86_64 / ARM64 设备切换需求。安装器按内核拆分前置条件、32 位 sing-box、每核原生高级配置和 mihomo 留待后续阶段；不把技术规划中的目标当成本版已实现功能。**
